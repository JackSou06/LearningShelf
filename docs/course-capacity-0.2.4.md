# 課程容量與失敗續作（0.2.4 build20）

載入的 JSON、Markdown 與圖片合計限制從20 MB提高至100 MB。原生載入器、原生裁圖總量、瀏覽器資料夾匯入、命令列驗證器與作者協議一致更新；瀏覽器與命令列共用 CourseCore.MAX_CONTENT_BYTES。ZIP 及解壓後全部檔案各維持200 MB，單份計畫／裁圖對照 JSON 的既有20 MB保護不變。沒有降低圖片品質、刪減教程或隱藏詳述。

## 從既有工作繼續

1. 退出正在執行的 LearningShelf。
2. 解壓 build20 App，將新版 LearningShelf.app 放到原使用位置，取代舊程式；不要刪除 Application Support 裡的課程、學習紀錄或 AuthoringJobs。
3. 開啟新版，進入「AI 製作課程」，在「製作紀錄」選取原來失敗的課程。
4. 按「重試並接續」。教程、審閱、轉製標為完成的階段會跳過，接著驗證、封裝及加入書架；不重新拖入教材，也不建立新工作。

App 的製作紀錄和書架存於 Application Support/LearningShelf，與 .app 程式分開。新版維持相同 bundle identifier 和資料位置。現有流程仍需可用 Codex 登入以進入續作，但已完成的階段不會因此重新生成。

## 已驗證

- 原生與 JavaScript 的總量上限均為100,000,000 bytes；實際超過20 MB的教材可載入，超過100 MB仍拒絕，拒絕時不讀入超大檔案內容。
- 命令列驗證器使用真正21 MB檔案，瀏覽器匯入另測文字、圖片與100 MB邊界。
- 使用卡在20 MB限制的完整工作副本續作，教程／審閱／轉製已完成。測試服務禁止任何AI生成，確認生成呼叫為0，教程、審閱、計畫及課程內容682個檔案的hash不變（原生驗證報告可更新），仍能驗證、封裝、複驗及匯入隔離書架。
- 原工作先另行完整備份，與副本逐檔核對關鍵檔案hash；沒有修改個人書架、原始工作狀態或重跑教程。

本機證據在dist/content-limit-review/；工作備份和個人課件不提交Git。此變更不包含圖片按需載入，100 MB仍是整門課載入量上限。
